# 工作原理（精简版）

> 完整的过程记录（含每次迭代的排查细节）在仓库外的个人笔记里；这里只留对外有价值的部分。

## 1. 通信链路

```
ControlCenterX (WinUI3 UI)  ──MQTT──▶  GCUBridge.exe (本机 broker, 127.0.0.1:13688)
                                            │
                                            └── BLE ──▶ 水冷坞硬件
```

控制中心界面不直接跟硬件说话：它订阅本机 MQTT broker（由 `GCUBridge.exe` 提供），由服务端负责 BLE 收发。
因此只要在同一个 broker 上按同样的报文格式发布状态，界面就会认为「水冷已连接」。

| 主题 | 方向 | 作用 |
|---|---|---|
| `BT_LC/Status` | 发布（retained） | 水冷坞状态：`connected` / `ConnectString` / `DevFWVersion` / `DevMACString` / `DeviceMacList` / `LC_MeterNormal` 等 |
| `BT_LC/Control` | 订阅 | 控制指令，如 `{"Action":"GETSTATUS"}` |
| `LCHWOC/Status` | 发布（retained） | 水冷超频：`Enable` / `Connected` / `Support` / 频率偏移 |
| `LCHWOC/Control` | 订阅 | HWOC 控制指令 |
| `Settings/DeviceSwitchItemStatus` | 订阅 | 设备开关（无线/蓝牙/摄像头/亮度） |

## 2. 判定链路（为什么这样发就算“已连接”）

1. 界面解析 `BT_LC/Status` 时用的是**小写键名 `connected`**（动态查找，不是强类型），且看 `ConnectString`；
   `ConnectString == "Connected"` → `AppSetting.IsLiquidCoolingConnected = true`；
   中间态是 `"IsConnectable"`（可连接但未连上），断开是 `"Disconnected"`。
2. `DevFWVersion` 会被界面进一步解析（固件版本号、机型标识），**字符串长度 < 23 会解析异常**，所以模拟值给足长度；
   `DeviceMacList` 不能为 `null`（给 `[""]` 或实际 MAC 均可）。
3. HWOC 那一栏来自 `LCHWOC/Status` 的 `Enable` / `Connected` / `Support`。
4. 界面是否显示水冷入口还受注册表门禁控制：
   `HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport\LiquidCoolingSupport = 1`（本机出厂即为 1）。

典型报文（本程序发布的内容）：

```json
{"src":"lc_sim","connected":true,"ConnectString":"Connected",
 "PumpDuty":0,"FanDuty":0,"LCLED_R":0,"LCLED_G":128,"LCLED_B":0,
 "LC_CoolingAuto":false,"LC_InputWater":false,"LC_PumpCtrl":"1","LC_FanCtrl":"1",
 "LC_UpdateFW":false,"DevFWVersion":"CoolingSystem LCT21001-SIM-v1.0.0",
 "DevMACString":"AA:BB:CC:00:11:22","DeviceMacList":["AA:BB:CC:00:11:22"],
 "LC_MeterNormal":true,"AutoConnect":false}
```

## 3. broker 鉴权

broker 对 clientId 有白名单校验，三者编号必须一致：

```
clientId = UWPClient_<N>            username = UWPClient_User_<N>            password = UWPClient_Pwd<N16位数字>_<N>
```

拒绝的表现：CONNACK 返回 2（标识符被拒）或 4（用户名/口令错误）。
官方界面用的是 `N=5`；本程序默认 `N=6`，失败时在若干编号间自动回退尝试。
（这几条常量是为了与官方组件互通而记录的协议细节。）

## 4. 状态覆盖与清理

- 启动时：可选地清理上一次留下的**自己发的** retained 消息（只匹配带 `"src":"lc_sim"` 的记录，不动控制中心自己的状态）；
- 运行中：按间隔重发 `BT_LC/Status` / `LCHWOC/Status` 维持状态；
- 停止/退出/关闭窗口：**一定**把两条状态覆盖回未连接（`connected:false` + `ConnectString:"Disconnected"`，`Enable:false`），
  这样即使程序异常退出，也不会留下“假已连接”的残留。

## 5. 界面实现要点

- 单文件 exe，`/target:winexe`，只用系统自带的 .NET Framework 4.x（`csc.exe` 编译），无第三方运行库；
- 无边框窗口：`FormBorderStyle.None` + `WS_THICKFRAME` + `WM_NCHITTEST` 自己实现缩放；
  `WM_NCCALCSIZE` 让客户区铺满整窗（去掉系统预留的边框带），`WM_NCPAINT`/`WM_NCACTIVATE` + `DWMNCRENDERING_POLICY` 阻止系统画标题条；
- 圆角：全局统一 `Md3.Rad = 12`，窗口 Region 用同一路径；
- 动画：自绘控件 + 16ms 动画泵（`TweenValue`/`Animator`），曲线取 OutCubic / InOutCubic / OutBack；
- 配色：Material 3 官方链路 —— CAM16 正逆变换 + HCT（Hue/Chroma/Tone）→ TonalPalette → SchemeTonalSpot，
  主色由桌面壁纸经「量化分桶 + HCT 打分」选出（同 Android 12 Monet 的思路）；可用 `--palette` 打印色板核对官方基线。

## 6. 已知环境坑

| 现象 | 原因 / 处理 |
|---|---|
| 打开时「Windows 已保护你的电脑」 | SmartScreen 对非公共 CA 签名的新文件的信誉判定。自用可关闭「检查应用和文件」，外发需买证书 |
| 托盘图标不出现 | 托盘登记受 UIPI 限制（非提权进程发消息被拦）或被安全软件（如火绒）拦；本程序会自检+重试，失败后询问是否以管理员重启 |
| 图标进了“溢出区” | Windows 11 默认行为；程序会写 `HKCU\Control Panel\NotifyIconSettings\<项>\IsPromoted=1` 尝试提升为常显 |
| 双击没反应 | 已有实例在运行（单实例互斥）；此时会**把已有窗口叫回来**，不会静默退出 |
