# 虚拟水冷坞（LiquidCooling Simulator）

目标：不买水冷坞、不动蓝牙，让 **机械革命控制中心 ControlCenterX 5.56.60.34** 认为"水冷已连接"。
做法：伪装控制中心内部 MQTT 状态上报，**不发一条蓝牙包**。

样本：`D:\DL\ControlCenterX_5.56.60.34_Mechrevo.zip`
（内含 `PreinstallKit/CCU.WinUI.msix` 界面包 + `ControlCenter_5.56.60.34_Mechrevo_GX.exe` Inno Setup 6.3.0 安装器）
本机已装同版本：`C:\Program Files\WindowsApps\CCU.WinUI_5.56.60.34_x64__wrbgcf7aesyd8` +
`C:\Program Files\OEM\机械革命控制中心\AiStoneService\{GCUBridge.exe,MyControlCenter\GCUService.exe}`

---

## 一、结论：水冷"已连接"是怎么被判定的

界面（CCU.WinUI，.NET 8 + WinUI 3，`CCUWinUI.dll`）**既不读 EC、也不连蓝牙**，
它只是个 MQTT 客户端；后台 `GCUService.exe` 才是蓝牙收发方，`GCUBridge.exe` 是本机 MQTT broker。

| 环节 | 事实（均在源码/实机确认） |
|---|---|
| broker | `127.0.0.1:13688`，进程 **GCUBridge.exe**（MQTTnet 内嵌，Costura 打包，方法体已加密，静态反编译拿不到函数体） |
| 鉴权 | **三元组白名单**，见第二节 |
| 界面订阅 | 45 个 topic，QoS0（`DataService/Topic.cs`） |
| 水冷 topic | `BT_LC/Control`(下发) / `BT_LC/Status`(上报) / `LCHWOC/Control` / `LCHWOC/Status` |
| 判定点 1 | `LiquidCoolingSettingViewModel.Service_DataChange`：`connected==true` 且 `ConnectString=="Connected"` → `AppSetting.IsLiquidCoolingConnected = true` |
| 判定点 2 | `CustomSettingPageViewModel`：同主题 → `IsLC_BT_Connect` / `FanSettingVisiable`；`LCHWOC/Status` 的 `Enable/Connected/Support` → `HWOCSwitch/HWOCConnected/HWOCSupport` |
| 页面门禁 | `HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport\LiquidCoolingSupport` |
| 握手 | 进水冷页后每 10s 发 `BT_LC/Control {"Action":"GETSTATUS"}` 直到收到状态 |

**两个必须踩准的解析坑**（踩错会让整个状态解析异常中断）：
- `DevFWVersion` 必须 ≥23 字符（界面 `Substring(0,22)` 比较 "CoolingSystem LCT21001"）；
- `DeviceMacList` 不能为 null（`.Count` 会 NRE）。

## 二、broker 鉴权规则（实机探测得出，本工具的关键）

`GCUBridge` 只放行**编号一致的三个字段**，编号必须对齐：

```
clientId = UWPClient_<N>          username = UWPClient_User_<N>       password = UWPClient_Pwd888881772688_<N>
```

实测（本机 13688）：

| 尝试 | CONNACK |
|---|---|
| `UWPClient_5` + `UWPClient_User_5` + `...Pwd..._5` | **0 = 接受** |
| `UWPClient_6..12` 用配套编号 | **0 = 接受** |
| 任意别的 clientId（`GCUService`/`LC_Simulator_1`/`UWPClient_0`…） | 2 = IdentifierRejected |
| 编号对但密码/用户名错 | 4 = BadUserNameOrPassword |

→ 所以第三方程序必须**换一个编号**（默认 **6**；官方界面固定占 5，用 5 会把界面顶下线，界面 5 秒后自动重连）。
协议用 MQTT 3.1.1（protocol name `MQTT`, level 4；MQTT 5 会被挂起无响应）。

## 五、使用步骤

1. 确认控制中心在跑（`GCUBridge.exe` 监听 13688）。
2. 只读观测（建议先做）：
   ```
   cd watercool-sim
   python lc_watch.py
   ```
   应打印一条 `BT_LC/Status`；按需在界面上点按钮还能看到 `BT_LC/Control` 原文。
3. 界面没有"水冷"入口时：管理员 PowerShell 跑 `.enable_lc_page.ps1`，重启控制中心。
4. 启动虚拟水冷坞：
   ```
   run_lc_sim.bat
   :: 或
   python lc_sim.py --verbose
   ```
   看到 `虚拟水冷坞已上线: clientId=UWPClient_6 ...` 即成功。
5. 控制中心 → 水冷页显示"已连接"，泵/风扇数值、超性能开关可用；首页雷达图随之变化。
6. `Ctrl+C` 退出。

参数：

```
--slot 6              使用 UWPClient_<N> 组合（默认 6；5 是官方界面占用）
--mac  XX:XX:...      伪装设备 MAC
--fw   <字符串>       固件版本（>=23 字符）；前缀特意不写 CoolingSystem LCT21001 可让界面
                      认为支持"风扇灯效"（IsLC_FanLEDSupport = true）
--interval 1.0        状态重发间隔
--reconnect-delay 3   界面点"断开"后自动重连秒数
--no-suppress         不压制真实服务的上报
--once / --offline    只发一次 / 反向发一次"未连接"并退出（清 retain）
--dry-run             只打印报文不联网
--verbose             打印收发报文
```

## 八、局限与进阶

1. 本工具压制的是**状态上报**。UI 侧（水冷页、雷达图、超频开关、风扇策略 `AppSetting.IsLiquidCoolingConnected`）会完全相信水冷在线；
   服务内部是否真的把 HWOC 写进 EC，取决于 `GCUService` 自己对 `LCHWOC/Control` 的处理——它的方法体被加密保护，静态反编译拿不到，
   但 `LiquidCooling` 类暴露了关键面：`CoolingModeECAddress = 1991`、`SetECSupport(bool)`、`WMILC_Condition(bool)`、
   `ConnectLC/DisconnectLC`、`PumpControl/FanControl/LEDControl`、`Get_Meter_State`。
   若发现"界面好了但实际超频没生效"，下一步就是动态侧：直接改 `LCHWOC\LiquidHWOC.json`（`HWOCEnable`），或对 `GCUService.exe` 做运行期 hook。
2. 插着真水冷坞时别开本工具，两边会互相覆盖状态。
3. 长跑建议 `--interval 1` 或更小，配合内置 watchdog，界面不会闪。

### 自动清理（重点）

| 时机 | 行为 |
|---|---|
| 点「停止模拟」 | 先把 `BT_LC/Status` / `LCHWOC/Status` 覆盖为**未连接**，再断开（可用复选框关掉） |

| 「一键清理残留」按钮 | 不启动模拟也能清，专门收拾上次留下的 retain |
| 程序启动时 | 只在 broker 上的 retain **确实带 `"src":"lc_sim"` 标记且仍显示已连接**时才清理——绝不碰真实设备的状态 |

清理用的报文就是真实服务的"未连接"结构（`connected:false, ConnectString:"Disconnected"` / `Enable:false, Connected:false`），
所以界面收到后立刻回到未连接，不留"界面以为开了超频"的窗口期。

## 十、换一台电脑还能不能用？

**程序本身随便拷**：单文件、AnyCPU、纯 .NET Framework 4.x + WinForms，无外部依赖、无配置文件、无机器绑定。
Win10/11 双击即可；Win7 SP1 / 8.1 装了 .NET Framework 4.x 也行。未签名，首次运行可能弹 SmartScreen「未知发布者」→ 选「仍要运行」。
**不需要管理员权限**（只有改注册表那一步需要）。

**能不能起作用，取决于目标机器这四条：**

| 前提 | 说明 | 不满足时的现象 |
|---|---|---|
| 装了同族控制中心 | 程序只跟**本机** MQTT broker 说话（默认 `127.0.0.1:13688`，进程 `GCUBridge.exe`） | 报「接不上 broker」 |
| broker 鉴权规则一致 | 只认 `UWPClient_<N>` / `UWPClient_User_<N>` / `UWPClient_Pwd888881772688_<N>` 且编号一致（软件会自动试 6→20、1→4、5） | 报「所有编号都被拒绝（CONNACK 2/4）」 |
| 机型支持水冷页面 | 入口由 `HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport\LiquidCoolingSupport` 决定 | 状态报上去了，但界面里根本没有水冷入口 → 先跑 `enable_lc_page.ps1` |
| 服务处理这些主题 | 同一安装包里就有 mechrevo / Machenike(机械师) / MCJ / monster / white / LightMaster / XMG OASIS 等分支，主题与字段基本一致，但只有 5.56.60.34 这台实测过 | 主题名/字段不同的版本需按新样本重新对齐 |

**换机器 30 秒自检（新版 GUI 已内置）**：
把 exe 拷过去 → 双击 → 点 **「测试连接」**（只读，不改任何状态）。它会打印：
1. 能否连上 broker、用哪个编号连上的；
2. 该机器上真实的 `BT_LC/Status`、`LCHWOC/Status` 报文。

- 能打出真实报文 → 这台机器可用，点「启动模拟」就行；
- 报「接不上 broker」→ 服务没装/没跑，或端口不是 13688（界面可直接改「主机/端口」，命令行用 `--host --port`）；
- 报「所有编号都被拒绝」→ 那台机器的鉴权规则不同，把它 `CCUWinUI.dll` 里的 `MQTTDataService` 或 `GCUBridge.exe` 给我，按它的规则改一版即可。

**注意**：目标机器上如果**真插着水冷坞**，别同时开本工具——两边会互相覆盖状态。

## 十二、复查语义修正（为什么有时只显示 2/3）

**原因**：控制中心界面**只有停在「水冷页」时**才会每 10 秒发一次 `BT_LC/Control {"Action":"GETSTATUS"}`。
你当时不在水冷页 → 观察期内收不到界面指令 → 旧版把它算成"未通过"，属于误报。

**现在的复查分两层，结论只看关键项：**

```
==== 启动复查（观察 6 秒）====
[OK] broker 已回读 BT_LC/Status：connected=true（发布链路通）        ← 关键项
[OK] broker 已回读 LCHWOC/Status：Enable/Connected/Support 全为真   ← 关键项
---- 以下为观察项（不影响上面结论）----
[..] 本次观察期内没收到界面指令 —— 这是正常的：界面只有停在「水冷页」时才会每 10 秒发一次 GETSTATUS。
     想验证就打开控制中心的水冷页，再点「复查」按钮
[OK] 服务端广播正常：收到 Settings/DeviceSwitchItemStatus（BTEnable=true），说明 GCUService 在线
[..] 期间真实服务没有抢报「未连接」（暂无干扰）
==== 复查结果：关键项 2/2 通过（虚拟水冷坞已生效）====
```

**本轮配套改动**：

## 十七、改用谷歌官方取色链路（HCT/CAM16）+ 修掉文字背景穿模

### 文字背景穿模的原因与修复

输入框（Md3Field）自绘时用了 g.Clear(P.Surface)，但它其实待在卡片里（卡片底色是 SurfaceContainerLow）——
于是每个输入框周围多出一块比卡片更亮的方块，标签文字看起来像「贴在色块上」，这就是穿模。
修复：输入框背景改成跟随父容器（ParentBg()：父是卡片就取卡片底色，否则取窗体底色），标签与描边周围不再出现色块。

### 取色换成官方实现

新文件 gui/MonetM3.cs（与 WaterCoolSim.cs 一起编译），按 material-color-utilities（Google，Apache-2.0）自行实现：

| 组件 | 说明 |
|---|---|
| Cam16Vc / Cam16 | 官方默认 ViewingConditions（D65、La=11.72、Lstar=50、surround=2）+ CAM16 正/逆变换（含官方那版不把 FL 计入适应的简化） |

## 二十、去掉左侧/上边多余的那圈边框

**原因**：为了支持无边框缩放，窗口加了 `WS_THICKFRAME`。Windows 会因此预留一圈非客户区（sizing frame），
WinForms 的客户区被内缩，露出的那圈由系统按默认底色绘制——就是你在左边和上边看到的多余浅色带。

**修复**：在 `WndProc` 里接管 `WM_NCCALCSIZE`：把 `NCCALCSIZE_PARAMS.rgrc0` 直接设成整个窗口矩形并返回 0，
等于告诉系统“客户区就是整个窗口”。最大化时不做该处理（最大化时系统把边框挪到屏幕外，本来就看不到）。

顺带补了两处布局触发点，避免客户区尺寸变化后底部内容被裁：`OnClientSizeChanged` 与 `Shown` 都调用 `LayoutForSize()`。

**实测**（起进程后用 GetWindowRect / GetClientRect / ClientToScreen 量）：

```
窗口: 587x491  客户区: 586x490
左侧非客户区: 0px   上边非客户区: 0px      ← 之前是 8px / 8px 量级
```

截图 ui.png：圆角边框直接贴着窗口边缘，左侧/上边不再有额外的浅色圈，底部提示也不再被裁。

### 2. 托盘图标为什么没有——实测结论

| 检查 | 结果 |
|---|---|
| 程序自身日志 | `[托盘] 图标已创建并显示` —— NotifyIcon 创建成功 |
| `Shell_NotifyIconGetRect` | 外壳未登记（explorer 里没有这个图标） |
| UI 自动化枚举任务栏 | 27 个元素里没有本程序 |
| 展开 Win11 溢出区（系统托盘溢出窗口） | 12 个图标（Chrome/NVIDIA/DeepSeek Harness/机械革命控制中心/火绒/UU远程/G HUB/IDM/DarkMode/安全中心/Wallpaper Engine）——**没有本程序** |

→ 不是「藏在溢出区看不见」，而是**根本没登记进去**。

本机环境下的原因（可解释全部现象）：从我的沙箱会话启动的进程拿的是**受限/低完整性令牌**——
同样一次 HKCU\Run 写入，`reg.exe`/PowerShell 成功，而程序内写入被拒；启动文件夹写入也被拒。
低完整性进程被 **UIPI** 阻止向 explorer 的托盘窗口发消息，`Shell_NotifyIcon` 于是静默失败。
另外本机装有**火绒安全软件**，它的 HIPS 也可能拦截托盘登记与 Run 键写入（你正常双击运行时若仍无图标，优先看它的拦截日志）。
还发现：**任务栏设了自动隐藏**（`StuckRects3[8]=2`），图标即使登记成功也要把鼠标移到屏幕底部或点 ^ 才看得到。

### 3. 为此加的安全兜底

- 启动时做一次外壳登记自检（`Shell_NotifyIconGetRect`），结果写日志、也显示在「本机信息」页（外壳登记 / 隐藏到托盘）；
- 若图标没被登记：**禁用「关闭时后台运行」**，点 ✕ 直接退出（不让窗口藏到找不回来）；
- 托盘创建成功后弹一次气泡提示，告诉用户去 ^ 溢出区把它拖出来固定。

## 二十八、修掉「失去焦点时冒出一条灰色标题条」

你截图里那条灰蓝色的带子（还带着窗口标题文字），是**系统在窗口失活时自己画的非客户区标题条**：
我们的窗口是无边框的，但加过 `WS_THICKFRAME / WS_MAXIMIZEBOX`，系统仍按「有标题条」处理，
激活时被自绘盖住看不出来，一失焦系统就把它画了出来。

三处修：

| 位置 | 做法 |
|---|---|
| `CreateParams` | `cp.Style &= ~0x00C00000` —— 明确去掉 `WS_CAPTION` |
| `WndProc` | 拦 `WM_NCPAINT`（返回 0）与 `WM_NCACTIVATE`（返回 1），不让系统重画非客户区 |
| `OnHandleCreated` | `DwmSetWindowAttribute(hwnd, DWMWA_NCRENDERING_POLICY, DWMNCRP_DISABLED)` —— 告诉 DWM 不要渲染边框/标题条 |

验证：截图模式新增一张「失焦状态」截图（用另一个窗体抢焦点后抓取），`ui.inactive.png`：

## 二十九、打开时的弹窗：不是 Defender，是提权确认（火绒/UAC）

### 实测环境事实

| 项 | 值 |
|---|---|
| Windows Defender | **完全关闭**（AntivirusEnabled=False、RealTime=False、AMRunningMode=Not running） |
| 真正在跑的杀软 | **火绒**（服务 HRWSCCtrl = Running） |
| UAC | EnableLUA=1、ConsentPromptBehaviorAdmin=0、PromptOnSecureDesktop=0 |
| 本程序 exe | 无 MOTW、Authenticode=Valid（自签名） |

→ 弹窗来源是「程序请求管理员权限」这类确认（上一版我把清单改成了 `requireAdministrator`，每次启动都要提权），
不是 Defender 的病毒告警。

### 为什么别人的个人软件不弹

1. 默认 **asInvoker**（不请求管理员权限）；
2. 不写开机启动项、不动注册表敏感位置、不注册托盘这类「系统加固」会盯的行为；
3. 发布版用**公共 CA 签发的代码签名证书**（SmartScreen 认得），我们这台只是本地自签名证书；正规软件还有下载/使用信誉分。

### 本版改法（按需提权）

- 清单回到 **asInvoker**：双击启动**不再有提权提示**（实测：清单 asInvoker，直接启动成功）；
- 托盘登记若被拦，次数用尽后程序**自己弹一次询问**：「要以管理员身份重新启动吗？」（你点"是"才提权这一次）；
- 选择会记住（`HKCU\Software\WaterCoolSim\AskElevate`：0=问 / 1=总是 / 2=不再问）；拒绝照样能用；
- `RelaunchElevated()` 用 `ShellExecute + runas` 重启自身。

想彻底没有框：把 `虚拟水冷坞.exe` 加进火绒信任区（火绒 → 信任区 → 添加文件），之后普通权限也能登记托盘图标。

## 三十、SmartScreen「Windows 已保护你的电脑」的真相与处理

弹窗原文：**「Microsoft Defender SmartScreen 阻止了无法识别的应用启动」**，发行者显示 `WaterCoolSim Local Code Signing`。
这不是病毒告警（本机 Defender 是关闭状态），而是 **SmartScreen 的发布者信誉检查**：我们的证书是**自签名**的，不是公共 CA 签发，
SmartScreen 不认它 → 弹「无法识别的应用」。

### 为什么别人的个人软件不弹

| 别人怎么做 | 我们之前 |
|---|---|
| 用公共 CA（DigiCert/Sectigo/SSL.com 等）签发的代码签名证书，签名带时间戳 | 自签名证书 |
| 文件有下载/使用信誉分 | 本地新文件，无信誉 |
| 不少小工具干脆不做 SmartScreen 也过不了，用户点「仍要运行」 | — |

**自签名证书在别人机器上永远过不了 SmartScreen**；要彻底解决只有买 CA 证书（含 EV 证书可立即获得信誉）。

### 本机已做的处理

1. **清单改回 `requireAdministrator`**（你要的提权启动）；
2. 签名**加上 DigiCert 时间戳**（`TimeStamperCertificate = DigiCert SHA256 RSA4096 Timestamp Responder 2026`）——签名长期有效；
3. 把自签名证书从「当前用户」升级装到**本机（LocalMachine）**的 受信任根 + 受信任发布者：
   ```
   certutil -addstore -f Root <cer>              exit=0
   certutil -addstore -f TrustedPublisher <cer>  exit=0
   Get-ChildItem Cert:\LocalMachine\Root            → 已包含 CN=WaterCoolSim Local Code Signing
   ```
   这是让 SmartScreen 认账的关键一步（它校验证书链到本机根存储）。

### 若仍弹，两个选择

- **关掉「检查应用和文件」**：`HKCU\Software\Microsoft\Windows\CurrentVersion\AppHost\EnableWebContentEvaluation = 0`（或 设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 关闭「检查应用和文件」）——对**所有**应用生效；
- **Unblock-File**：如果这份 exe 是从网上/网盘拿的副本（带 MOTW），`Unblock-File <exe>` 解除后再运行；本地构建的这份没有 MOTW。

### 撤销本机证书信任

```
Get-ChildItem Cert:\LocalMachine\Root,Cert:\LocalMachine\TrustedPublisher |
  Where-Object { $_.Subject -like '*WaterCoolSim*' } | Remove-Item
```

## 三十一、彻底关掉 SmartScreen 的应用检查

排查结论：全机器只有一份 exe（`D:\deepseek\watercool-sim\虚拟水冷坞.exe`），**无 MOTW**、签名 Valid，
弹窗纯粹是 SmartScreen「检查应用和文件」对**非公共 CA 签名的新文件**做信誉判定 —— 和文件本身无关。

### 已做（彻底解决）

| 位置 | 值 | 结果 |
|---|---|---|
| `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppHost\EnableWebContentEvaluation` | **0** | 提权写入 exit=0 ✓ |
| `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\AppHost\EnableWebContentEvaluation` | **0** | ✓ |

对应界面：设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 「检查应用和文件」= 关。
之后本机任何程序都不会再弹「Windows 已保护你的电脑」。

### 恢复方法（想开回来）

```
# 管理员
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppHost" /v EnableWebContentEvaluation /t REG_DWORD /d 1 /f
# 当前用户
reg add "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\AppHost" /v EnableWebContentEvaluation /t REG_DWORD /d 1 /f
```

### 代价

关闭后系统不再对下载的可执行文件做信誉拦截（安全性略降）。要分发给别人时，仍需购买公共 CA 的代码签名证书——
自签名证书在别人机器上必然被 SmartScreen 拦（这是设计如此）。
