# 适配第三方控制台

本程序默认按 **机械革命/同方 ControlCenterX（GCUBridge，本地 MQTT broker 127.0.0.1:13688）** 的协议工作。
为了适配别的控制台（第三方控制软件、别的 OEM 的控制中心、或你自己写的小控制台），内置了一套**配置（profile）机制**：
**改配置、不用重新编译**。

## 配置文件放在哪

```
<exe 同目录>/profiles/*.ini
```

首次运行程序会生成两个示例：

| 文件 | 作用 |
|---|---|
| `01-mechrevo.ini` | 原厂默认（就是本程序一直以来的行为） |
| `99-custom-template.ini` | **第三方适配模板**：复制一份改名，按自己控制台的协议填 |

程序启动时按文件名顺序逐个试连，**哪个能连上就用哪个**，并在日志与「本机信息」页写明当前用的配置。
## 先搞清楚「你的第三方控制台」长什么样（`--discover`）

程序不预设品牌：`--discover` 会把本机**所有像控制台的东西**列出来——

1. 名字像控制台/OEM 硬件工具的进程（gcu / armoury / legion / nitro / omen / predator / nbfc / fanctrl / liquid / thermal …）；
2. 名字或显示名像控制台的服务（含状态与启动方式）；
3. **每一个本地监听端口**，并逐个做 MQTT 实连验证，标出 `★ MQTT 且认证通过` / `◆ MQTT broker（认证被拒）` / `· 不是 MQTT`；
4. 当前 `profiles\*.ini` 列表。

```
虚拟水冷坞.exe --discover
```

把第 3 段里标 ★/◆ 的端口（以及你认识的那个控制台名字）发出来，就能给它写一份 profile。

## 如果第三方控制台没有 broker

有些控制台是**直接跟 EC/驱动通信**的（没有 MQTT broker），端口扫描自然找不到。这种情况本程序的 profile 机制帮不上，
需要单独实现它的接口（通常是通过它的服务、共享内存、或者它的 DLL/命令行）。
把控制台名字或安装目录发我，我看它的接口再决定怎么写。
