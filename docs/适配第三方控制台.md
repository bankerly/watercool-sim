# 适配第三方控制台

本程序默认按 **机械革命/同方 ControlCenterX（GCUBridge，本地 MQTT broker 127.0.0.1:13688）** 的协议工作。
为了适配别的控制台（第三方控制软件、别的 OEM 的控制中心、或你自己写的小控制台），内置了一套**配置（profile）机制**：
**改配置、不用重新编译**。

## 配置文件放在哪

```
<exe 同目录>/profiles/*.ini
```

首次运行程序会生成两个示例：

| 文件 | 作用 |
|---|---|
| `01-mechrevo.ini` | 原厂默认（就是本程序一直以来的行为） |
| `99-custom-template.ini` | **第三方适配模板**：复制一份改名，按自己控制台的协议填 |

程序启动时按文件名顺序逐个试连，**哪个能连上就用哪个**，并在日志与「本机信息」页写明当前用的配置。

## 配置字段

```ini
name=第三方控制台示例            # 显示名
host=127.0.0.1                  # broker 地址
port=1883                       # broker 端口（autoport=1 时会自动搜索）
autoport=1                      # 1=启动时自动找端口（枚举本机监听端口+MQTT 实连验证）
slots=6,7,8,9,10,5              # clientId 编号候选顺序（认证需要编号的控制台用）
clientid=client_{slot}          # clientId 模板，{slot} 会被替换
username=                       # 用户名模板（不需要认证就留空）
password=                       # 密码模板
topic.status=WaterCooling/Status          # 水冷状态主题（发布，retained）
topic.control=WaterCooling/Control        # 控制主题（订阅）
topic.hwoc.status=WaterCooling/HWOC/Status
topic.hwoc.control=WaterCooling/HWOC/Control
topic.devswitches=                        # 设备开关主题（没有就留空）
probe.key=connected                       # 自检判定用的关键字段名
payload.connected={"vendor":"x","connected":true}      # 已连接报文（留空=用内置机械革命报文）
payload.disconnected={"vendor":"x","connected":false}  # 未连接/清理报文
payload.hwoc.on={...}                     # 超频开会话（可留空）
payload.hwoc.off={...}                    # 超频关会话（可留空）
```

报文模板里可用占位符：

| 占位符 | 含义 |
|---|---|
| `{mac}` | 界面「设备 MAC」里的值 |
| `{fw}` | 界面「固件版本」里的值 |
| `{src}` | 固定为 `lc_sim`（程序自己发的消息都带这个标记，便于只清理自己的残留） |

## 命令行

```
虚拟水冷坞.exe --profiles     列出 profiles 目录里的所有配置，并逐个测试能否连上
虚拟水冷坞.exe --portscan     枚举本机监听端口并做 MQTT 实连验证（找端口用）
```

## 实测例子（本仓库自测用）

写一个 `00-thirdparty-test.ini`（broker 端口 13777、主题 `XLC/Status`、自定义报文），先起一个测试 broker，再跑：

```
虚拟水冷坞.exe --cleanup
```

订阅端在 `XLC/Status` 上收到：

```json
{"vendor":"thirdparty","connected":false,"state":"NO_DOCK","mac":"AA:BB:CC:00:11:22"}
```

→ 端口、主题、报文三样都按配置走，说明对第三方控制台的适配链路是通的。

## 适配别的控制台时要注意什么

1. **它得有个本地 broker**（MQTT）。如果第三方控制台是直接跟硬件驱动通信（没有 broker），本程序的 profile 机制帮不上，需要单独实现它的 API。
2. **认证**：如果它要求用户名/密码/证书，`username`/`password` 模板照填；`slots` 里给需要的编号。
3. **报文格式**：实在不确定就用 `--probe`（只读）抓一次真实报文，照着填 `payload.*`。
4. **清理**：程序发的报文都带 `{src}`=`lc_sim`，停止/退出时只会把自己发的残留覆盖掉。
